# 用户登录模块 · 接口文档

> 适用版本：Spring Boot 4.1.2 / Java 17
> 模块范围：登录、获取当前用户、退出登录
> 默认地址：`http://localhost:8080`
> 在线调试（Swagger UI）：`http://localhost:8080/swagger-ui.html`

---

## 一、通用约定

### 1.1 请求格式

| 项目 | 约定 |
| --- | --- |
| 请求体格式 | `Content-Type: application/json` |
| 字符编码 | UTF-8 |
| 鉴权方式 | 请求头 `Authorization: Bearer {token}`（也兼容直接放 token 或 `token: {token}`） |
| Token 有效期 | 1440 分钟（24 小时），配置项 `app.auth.token-expire-minutes` |

### 1.2 统一响应体

```json
{
  "code": 1,
  "msg": "",
  "data": {}
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `code` | number | **1 = 成功，0 = 失败**，只有这两个值 |
| `msg` | string | **只有失败时才有内容**；成功时为空字符串，可直接弹给用户看 |
| `data` | object \| null | 业务数据；失败时为 `null` |

### 1.3 状态码约定

HTTP 状态码表示请求结果类别，响应体 `code` 表示业务成功与否，两者配合使用：

| 场景 | HTTP 状态码 | 响应体 `code` | 响应体 `msg` |
| --- | --- | --- | --- |
| 成功 | `200` | `1` | `""` |
| 参数校验失败 / JSON 格式错误 | `400` | `0` | 具体原因 |
| 未登录 / token 缺失、无效、过期 | `401` | `0` | `请先登录` 等 |
| 用户名或密码错误 | `401` | `0` | `用户名或密码错误` |
| 无权限 | `403` | `0` | `没有访问权限` |
| 接口路径不存在 | `404` | `0` | `接口不存在: /xxx` |
| 请求方式不支持 | `405` | `0` | `不支持 GET 请求...` |
| Content-Type 不支持 | `415` | `0` | `不支持的 Content-Type` |
| 服务器内部错误 | `500` | `0` | `服务器开小差了，请稍后再试` |

> 客户端建议先判断 HTTP 状态码：`401` 统一跳回登录页；其余情况再读响应体 `code`/`msg` 展示提示。
>
> 注意：服务端默认拦截所有请求，只有 `/user/login` 和 Swagger 文档路径不需要 token。
> 因此未登录访问一个不存在的路径时，会先返回 `401`，而不是 `404`；携带有效 token 后访问不存在的路径才返回 `404`。

| --- | --- | --- |
| `admin` | `123456` | 管理员 |

## 二、登录

### 2.1 基本信息

| 项目 | 内容 |
| --- | --- |
| 接口地址 | `POST /user/login` |
| 是否需要登录 | 否 |
| Content-Type | `application/json` |

### 2.2 请求体

```json
{
  "userName": "admin",
  "password": "123456"
}
```

| 字段 | 类型 | 必填 | 校验规则 | 说明 |
| --- | --- | --- | --- | --- |
| `userName` | string | 是 | 非空，最长 32 字符 | 登录账号 |
| `password` | string | 是 | 非空，长度 6–32 | 登录密码（明文传输，生产环境需 HTTPS） |

### 2.3 成功响应

**HTTP 200**

```json
{
  "code": 1,
  "msg": "",
  "data": {
    "token": "097309c4321a406a93e2914c54083cf7",
    "userId": 1,
    "userName": "admin",
    "nickName": "管理员"
  }
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `data.token` | string | 登录凭证，后续请求放入 `Authorization: Bearer {token}` |
| `data.userId` | number | 用户 ID |
| `data.userName` | string | 登录账号 |
| `data.nickName` | string | 昵称，界面展示用 |

### 2.4 失败响应

**用户名或密码错误 —— HTTP 401**

```json
{
  "code": 0,
  "msg": "用户名或密码错误",
  "data": null
}
```

> 用户不存在与密码错误返回完全相同的提示，防止账号枚举。

**用户名为空 —— HTTP 400**

```json
{
  "code": 0,
  "msg": "用户名不能为空",
  "data": null
}
```

**密码长度不合法 —— HTTP 400**

```json
{
  "code": 0,
  "msg": "密码长度必须在 6 到 32 个字符之间",
  "data": null
}
```

**请求体不是合法 JSON —— HTTP 400**

```json
{
  "code": 0,
  "msg": "请求体格式不正确，请传入合法的 JSON",
  "data": null
}
```

## 三、获取当前登录用户

### 3.1 基本信息

| 项目 | 内容 |
| --- | --- |
| 接口地址 | `GET /user/info` |
| 是否需要登录 | 是 |
| 请求头 | `Authorization: Bearer {token}` |

无请求体、无查询参数。

### 3.2 成功响应

**HTTP 200**

```json
{
  "code": 1,
  "msg": "",
  "data": {
    "token": "097309c4321a406a93e2914c54083cf7",
    "userId": 1,
    "userName": "admin",
    "nickName": "管理员"
  }
}
```

> 该接口复用登录返回的 `LoginResult`，`data.token` 即当前请求携带的 token。

### 3.3 失败响应

**未携带 token —— HTTP 401**

```json
{
  "code": 0,
  "msg": "请先登录",
  "data": null
}
```

**token 无效或已退出 —— HTTP 401**

```json
{
  "code": 0,
  "msg": "登录已失效，请重新登录",
  "data": null
}
```

**token 过期 —— HTTP 401**

```json
{
  "code": 0,
  "msg": "登录已过期，请重新登录",
  "data": null
}
```

## 四、退出登录

### 4.1 基本信息

| 项目 | 内容 |
| --- | --- |
| 接口地址 | `POST /user/logout` |
| 是否需要登录 | 是 |
| 请求头 | `Authorization: Bearer {token}` |

无请求体。服务端会把该 token 从会话表中删除，之后再用它访问需要登录的接口会返回 401。

### 4.2 成功响应

**HTTP 200**

```json
{
  "code": 1,
  "msg": "",
  "data": null
}
```

### 4.3 失败响应

**未携带 token —— HTTP 401**

```json
{
  "code": 0,
  "msg": "请先登录",
  "data": null
}
```

**token 已失效 —— HTTP 401**

```json
{
  "code": 0,
  "msg": "登录已失效，请重新登录",
  "data": null
}
```

## 五、登录页调用流程

```text
用户输入账号密码
        │
        ▼
POST /user/login
        │
        ├── HTTP 200 + code=1  → 保存 token 和用户信息 → 进入首页
        ├── HTTP 400           → 展示 msg（参数不合法）
        └── HTTP 401           → 展示 msg（用户名或密码错误）

进入首页后（可选）
        │
        ▼
GET /user/info  → 校验 token 是否仍然有效，并刷新用户信息

点击退出
        │
        ▼
POST /user/logout → 清除本地 token → 回到登录页
```

### 鸿蒙端示例

```ts
// 登录
const res = await request.post<LoginResult>('/user/login', {
  userName,
  password
});
AppStorage.setOrCreate<string>('TOKEN', res.token);

// 后续请求带 token
const user = await request.get<LoginResult>('/user/info', undefined, {
  header: { Authorization: `Bearer ${AppStorage.get<string>('TOKEN')}` }
});

// 退出
await request.post('/user/logout', undefined, {
  header: { Authorization: `Bearer ${AppStorage.get<string>('TOKEN')}` }
});
AppStorage.delete('TOKEN');
```

## 六、curl 调试示例

```bash
# 登录
curl -i -X POST http://localhost:8080/user/login \
  -H "Content-Type: application/json" \
  -d '{"userName":"admin","password":"123456"}'

# 获取当前用户（把 TOKEN 换成上一步返回的 token）
curl -i http://localhost:8080/user/info \
  -H "Authorization: Bearer TOKEN"

# 退出登录
curl -i -X POST http://localhost:8080/user/logout \
  -H "Authorization: Bearer TOKEN"

# 验证退出后 token 已失效（应返回 HTTP 401）
curl -i http://localhost:8080/user/info \
  -H "Authorization: Bearer TOKEN"
```

## 七、实现说明与注意事项

1. **用户数据存在 MySQL**（MyBatis-Plus 的 `UserMapper` → `harmony_test.user` 表）。建库建表需要手动执行 `db/init.sql`，应用启动时不会自动改数据库结构。
2. **token 存在内存里**（`TokenStore`），重启服务后所有已登录会话失效，需要重新登录。
3. **密码使用 BCrypt 加密存储**，数据库中永远不存明文；响应体也不会返回密码字段。
4. **登录失败与未登录都返回 401**，客户端应通过 `msg` 区分具体原因。
5. **数据库连接**：默认 `localhost:3306/harmony_test`、用户 `root`，密码通过 `DB_PASSWORD` 环境变量传入；也可用 `DB_URL`、`DB_USERNAME` 覆盖。
6. **测试账号**：`init.sql` 会插入 `admin`（密码 `123456`）。
7. **上线前必须**：改用 HTTPS、token 换成 JWT 或 Redis、增加登录失败次数限制与验证码。
